# Mac 手动框选跟踪与 MuJoCo 跟随计划

更新：2026-09-24。状态：Mac 摄像头手动框选效果已由用户确认可用；UR5 Home 姿态已改为夹爪水平朝 -Y；摄像头映射现在将框选物品显示为 TCP 前方固定距离的独立 MuJoCo 标记。真实摄像头与仿真的组合运行仍需人工联调。

## 本轮目标与已定范围

先完成一条可控的演示闭环：**手动框选一个物品 → 摄像头持续跟踪 → 在夹爪前方固定距离的平面内移动物品标记 → 可选地让 UR5 跟随并保持夹爪到标记的距离**。不把自动识别“手是否拿着物品”作为本轮前置条件；该能力单独留到后续阶段评估。

现有摄像头入口是 `.venv/bin/python -m ur5_mujoco.vision`。恰好检测到一只手时，按 `s` 拖框建立 CSRT 目标；跟踪结果已有 `frame_id`、单调时钟时间戳、`track_id`、状态、像素框和初始化来源。该时间戳来自主机取帧时刻，不是摄像头曝光时刻。CSRT 需要人工给出的初始框，不能判断物品是否仍拿在手上，也可能漂移。

仿真运行器以 100 Hz 驱动阻尼雅可比 TCP 控制器，物理步长为 2 ms；TCP 是夹爪 `pinch` 中心。Home 姿态中夹爪前向轴水平指向 -Y，夹爪开口沿水平 X 轴。相机跟随模式采用 0.08 m/s 的 TCP 线速度上限和 0.45 rad/s 的关节速度上限；普通程序轨迹沿用默认控制参数。程序轨迹的验收不能替代摄像头到仿真的闭环验收。

## 集成数据流

```text
Mac 摄像头 → 最新帧采集 → 手部提示 + 人工框选 → CSRT 跟踪
    → 最新有效二维观测 → 固定距离平面映射 → MuJoCo 物品标记
    → （可选）TCP 跟随控制器 → UR5 + 2F-85
```

各阶段之间只保留最新观测，不排队处理过期帧。控制循环仍以墙钟时间运行 100 Hz；视觉可以按摄像头实际帧率更新。摄像头时间戳和失效超时都使用同一主机的单调时钟。

## 阶段 4A：定义视觉到控制的接口

保留现有跟踪观测字段，并增加图像宽高与归一化框中心 `center_uv=(u,v)`，其中图像左上角为 `(0,0)`、右下角为 `(1,1)`。控制端读取最新观测的线程安全单槽邮箱，禁止使用积压队列。

只有同时满足以下条件时观测才可驱动目标：状态为 `TRACKING`、框存在且在图像内、时间戳新鲜、`track_id` 与当前人工选定目标一致。`PAUSED`、`LOST`、摄像头错误、尺寸变化、过期观测或无效框都不得继续发送新的视觉目标。

使用两个进程保持两套窗口各自稳定：macOS 的 `mjpython` 进程拥有 MuJoCo 查看器和 100 Hz 仿真循环；普通 Python 子进程拥有摄像头、MediaPipe、CSRT 与 OpenCV 交互。摄像头进程通过容量为 1 的观测队列发送最新观测，另用短控制队列发送启动/暂停/退出命令；仿真端按墙钟时间检查新鲜度，不积压旧帧。MuJoCo 窗口保持打开，直到用户关闭任一窗口或指定的运行时限到达。

## 阶段 4B：把 2D 框选显示成夹爪前方的物品标记

按 `s` 完成框选后立即建立映射锚点。黄色物品标记初始放在 TCP 沿夹爪前向轴 0.30 m 的位置；该距离可用 `--object-distance` 调整。之后将框中心相对锚点的左右、上下移动映射到垂直于夹爪前向轴的 X-Z 平面，标记深度保持不变。未选择物体时隐藏物品标记。该距离是无深度摄像头条件下的场景假设，不是物体真实深度测量。

第一版映射参数先设为可调整配置：左右移动对应基座平面内一个轴，上下对应竖直轴；图像轴方向、机器人轴方向和正负号先通过目标标记验证后固定。可先将单侧行程限制在约 50 mm（左右）和 40 mm（上下），再根据 MuJoCo 中的可达性调整。超出工作区的目标裁剪到边界。

默认的**物品标记预览模式**在框选确认后自动启动：只移动独立的黄色物品标记，机械臂保持在启动姿态。原有 TCP 控制标记在相机模式中隐藏。依次测试中心、左右、上下和四角，确认方向、比例、中心锚定及边界行为。确认通过后，才用 `--move-arm` 并按空格启用仿真机械臂跟随。机械臂跟随时，TCP 目标取物品标记沿夹爪反向偏移设定距离的位置。

## 阶段 4C：启用低速 TCP 跟随

- 框选确认后物品标记立即显示并开始映射；机械臂跟随默认关闭。使用 `--move-arm` 时，空格开始或暂停机械臂跟随，暂停时机械臂保持当前位置而物品标记继续跟随。
- 按 `s` 重新框选前隐藏旧标记；框选取消时继续隐藏。
- 首版目标速度限制为 0.02 m/s，低于控制器现有 0.05 m/s 上限；目标还需做轻度平滑和加速度限制，避免像素抖动直接变成 TCP 抖动。
- 初始观测年龄上限设为 150 ms。按 0.02 m/s 计算，这对应约 3 mm 的单纯延迟位移；联调时记录观测年龄 P95。如 Mac 实测无法稳定满足，就降低目标速度或根据误差预算收紧设置，不让过期观测继续驱动机械臂。
- 遇到短暂 `PAUSED` 或图像延迟时，标记保持在最后有效位置并等待追踪恢复；持续失锁、超出恢复窗口或摄像头故障时，隐藏标记，机械臂停止跟随并保持当前位置。
- 失锁后重新按 `s` 框选会生成新锚点；新标记从当前 TCP 前方设定距离开始。
- 画面持续显示手数、跟踪状态、目标编号、观测年龄、仿真跟随开关和暂停原因。CSV 至少记录帧号/时间戳、框中心、跟踪状态、观测年龄、映射及限速后的 TCP 目标、实际 TCP、跟随开关和暂停原因。

## 分阶段验收

1. **摄像头与人工跟踪：**确认 `s` 可选取目标，框随物体移动；遮挡或失效会显示暂停/失锁而非继续显示为正常跟踪；重新框选会生成新目标编号。CSRT 只作为人工初始化后的跟踪器。
2. **标记映射：**机器人关节不动时，目标标记按左右、上下移动，中心回到锚点；四角都被工作区限制，正负方向正确。
3. **低速联调：**慢速左右、上下和圆弧移动，连续运行 60 秒；暂用现有仿真目标 RMS 误差 ≤10 mm、峰值 ≤25 mm、实测关节速度 ≤0.3 rad/s 作为观察门槛，并同时报告视觉延迟与目标限速情况。
4. **失效与恢复：**覆盖镜头、目标出画、CSRT 失锁、摄像头停止取帧、快速移动和重新框选；无效或过期观测不能继续推动目标，恢复时新目标从当前 TCP 位置起步，无位置跳变。
5. **长时间运行：**确认控制循环保持 100 Hz、视觉更新不积压、日志可将视觉偏差、映射偏差和 TCP 跟踪偏差分开检查。若跟踪框抖动或人工移动导致未达到误差门槛，记录结果并先调低映射比例/速度，再决定是否通过。

当前可用摄像头的处理基准曾测得约 15.6 FPS、手部推理延迟 P95 约 13 ms；这不是闭环端到端延迟。当前 CSRT 自动化检查只覆盖合成移动目标、无效边界框和帧尺寸变化，不代表复杂背景、遮挡或真实摄像头定位精度。

## 后续：自动发现手持物品

HOIST-Former 依赖 CUDA，当前 Mac 环境不能按官方依赖直接部署；此前 Apple Vision 前景分割和 SAM ViT-B 的本机测试也没有达到实时、独立物品候选的要求。因此自动判断“手里是否拿着物品”仍未验证，但它不阻塞本轮手动框选到 MuJoCo 的闭环。

自动发现能力以后单独验收：多类持物正例、空手/桌面物品/仅触碰等负例、误锁率、锁定耗时、帧率和遮挡恢复。放下物品时，手动 CSRT 可能继续跟踪原物体，所以当前依靠用户暂停、失锁或重新框选处理，不宣称能自动判断“已放下”。

后续若迁移到 D435 或真机，还要单独完成物品有效深度提取、相机到机器人基座标定、三维坐标验证和真机安全限速；本轮二维仿真映射不构成这些能力的验证。
